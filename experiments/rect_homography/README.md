# 平面矩形重投影与贴图（不用相机参数）

> 讨论记录 + 结论 + 推导 + 可运行示例。
> 场景：已知一个平面矩形在相机中投影的四个角点像素坐标，**不知道相机内参/外参**。

---

## 0. 一句话结论

| 问题 | 能 / 不能 | 做法 |
| --- | --- | --- |
| 边长改变、中心位姿不变时，预测新的四角像素 | **能，且精确** | 四点 DLT 求单应 `H`，新角点 = `H·(±a′,±b′)` |
| 把一张与矩形同尺寸的图片投影进新矩形 | **能** | `W = H·A`，一次 `warpPerspective` |

根本原因：**矩形所在平面 → 图像平面严格是一个单应变换**，所有相机内参外参都被这个 3×3 矩阵吸收掉了。
只要四点不共线、光心不在矩形平面上，几何部分就完全由 `H` 决定，与相机无关。

---

## 1. 问题一：预测变换后的四个角点

### 1.1 问题

已知：矩形（半边长 `a, b`）投影后的四个角点像素 `p1..p4`。
求：边长变为 `a′, b′`、**矩形中心位姿相对相机不变**时，四个角点的像素。

### 1.2 结论

能。不需要任何相机参数，也不需要恢复位姿。无噪声时结果**精确且唯一**。

### 1.3 推导

设矩形中心在相机系下为 `C`，两条边方向单位向量 `u, v`，法向 `n = u×v`。
角点在矩形本体系里是 `(±a, ±b, 0)`。针孔投影：

    s·[u_px, v_px, 1]ᵀ = K·(R·X_rect + t)

把 `X_rect = X·u + Y·v + C` 代入：

    [ũ, ṽ, 1]ᵀ ∝ K·(X·a₁ + Y·a₂ + C_c) = H·[X, Y, 1]ᵀ

    其中  a₁ = R·u,  a₂ = R·v,  C_c = R·C + t（中心的相机坐标）
          H = K·[a₁  a₂  C_c]      ← 3×3，尺度无关，8 个自由度

两个关键事实：

1. 平面 → 图像是**单应**，`K, R, t` 全被 `H` 吸收。4 组点对应给 8 个方程，`H` 唯一确定。
2. 边长改变而中心位姿不变 ⇒ 新角点在同一平面坐标系里只是坐标变成 `(±a′, ±b′)`，
   即**平面内绕中心的一次仿射缩放**。

所以：

    [u′, v′, 1]ᵀ ∝ H · [±a′, ±b′, 1]ᵀ

> 注意：这个方法与“矩形”无关，任何**共面四点**都成立。也不限于等比缩放——
> `a` 和 `b` 可以独立变化。

### 1.4 算法

1. 给四个像素点配上平面坐标：`(-a,-b), (a,-b), (a,b), (-a,b)`（顺序与绕向必须一致）。
2. 四点 DLT 求 `H`（8×8 线性方程组，固定 `h33=1`；或 SVD）。
3. 新平面坐标：`(-a′,-b′), (a′,-b′), (a′,b′), (-a′,b′)`。
4. 用 `H` 变换，除以第三分量。

DLT 方程（每个对应点两行）：

    h11·X + h12·Y + h13 - u·(h31·X + h32·Y + h33) = 0
    h21·X + h22·Y + h23 - v·(h31·X + h32·Y + h33) = 0

### 1.5 代码

Python（见 `rect_homography_demo.py`）：

    from rect_homography_demo import solve_H, apply_H, rect_plane
    H = solve_H(rect_plane(a, b), old_px)          # 四点 DLT
    new_px = apply_H(H, rect_plane(a2, b2))        # 新角点像素

OpenCV（C++）：

    std::vector<cv::Point2d> plane{{-a,-b}, {a,-b}, {a,b}, {-a,b}};
    std::vector<cv::Point2d> pix = /* 已知四角像素，顺序绕向一致 */;
    cv::Mat H = cv::findHomography(plane, pix, 0);          // 恰好 4 点 -> 精确 DLT

    std::vector<cv::Point2d> plane2{{-a2,-b2}, {a2,-b2}, {a2,b2}, {-a2,b2}};
    std::vector<cv::Point2d> pix2;
    cv::perspectiveTransform(plane2, pix2, H);              // 新角点像素

### 1.6 数值验证

随机生成 `K, R, t` 造真值，但把相机参数藏起来不给算法：

| 项目 | 结果 |
| --- | --- |
| 单次示例，边长独立改为 1.3× / 0.8× | 最大误差 `1.1e-13 px` |
| 单次示例，边长改成 2.0× / 2.0× | 最大误差 `3.4e-13 px` |
| 2000 组随机相机/位姿/矩形 | 最大相对误差 `9e-10`（机器精度） |

结论：无噪声时是**精确解**，不是近似。

### 1.7 退化条件

    det H = det K · (n·C_c)

`n·C_c = 0` ⇔ **相机光心落在矩形所在平面上**。此时矩形被投影成一条线段，
四个角点共线，`H` 奇异，问题无解（`np.linalg.solve` 会报奇异矩阵）。
换句话说：只要不是“正侧着看”矩形，就没问题。

### 1.8 噪声敏感性

四个点恰好把 `H` 定死，没有冗余，且新角点是**外插**，所以噪声会被放大。
实测（角点加 1 px 高斯噪声，均匀缩放 `s` 倍，300 次统计）：

| 缩放 s | 中位误差 | p95 |
| --- | --- | --- |
| 0.5× | 1.1 px | 2.2 px |
| 1.0× | 1.7 px | 2.7 px |
| 1.5× | 3.3 px | 6.1 px |
| 2.0× | 6.0 px | 14.3 px |
| 3.0× | 15.8 px | 77.4 px |

改善手段：多帧/多尺度多点最小二乘拟合 `H`；或已知 `K` 时走 `solvePnP`(IPPE)
分解出位姿再重投影。

### 1.9 什么时候不成立

- 矩形**离开原平面**（中心位置或姿态变了）：`H` 换了，必须重新知道位姿或相机参数。
- 平面内变化（改边长、沿边平移、绕法向旋转）都可以，因为它们都是平面内的单应/仿射。

## 2. 问题二：把一张图片投影进新矩形

### 2.1 结论

能。仍然是“再乘一个 3×3 矩阵”，依旧不需要相机参数。

`H` 已经把**矩形平面 (X,Y)** 映射到**像素 (u,v)**；图片是定义在这个平面上的纹理，
所以只要把图片的像素坐标映射到矩形平面坐标，再套 `H`。

### 2.2 两种情形

**A) 图案是一张独立图片 `T`（wt×ht），贴到矩形表面**

    X = -a′ + x·2a′/wt
    Y = +b′ - y·2b′/ht        ← y 取负：图像 y 向下、平面 Y 向上

    A = [[2a′/wt,  0,       -a′],
         [0,      -2b′/ht,   b′],
         [0,       0,         1 ]]

    W = H · A                  （图案像素 → 图像像素）

**B) 图案就是旧矩形在图像里已经呈现的内容，按新边长重新渲染**

    M = H · S · H⁻¹,   S = diag(a′/a, b′/b, 1)

可解析证明 `M·W_old ≡ W_new`，所以不必“先拉正再投影”两步。

### 2.3 代码

    # 情形 A
    W = H @ tex_to_plane(a2, b2, wt, ht)
    warped = cv2.warpPerspective(tex, W, (Wc, Hc),
                                 flags=cv2.INTER_LINEAR,
                                 borderMode=cv2.BORDER_TRANSPARENT)
    # 软边合成
    m = cv2.warpPerspective(np.full((ht, wt), 255, np.uint8), W, (Wc, Hc))
    dst = dst * (1 - m/255)[..., None] + warped * (m/255)[..., None]

更省事的等价写法（不用手推 `A`，但**四角顺序与绕向必须对应**）：

    # 图案四角 TL,TR,BR,BL  ↔  P4,P3,P2,P1
    W = cv2.getPerspectiveTransform(
            np.float32([[0, 0], [wt, 0], [wt, ht], [0, ht]]),
            new_px[[3, 2, 1, 0]].astype(np.float32))
    cv2.warpPerspective(tex, dst, W, (Wc, Hc), cv2.INTER_LINEAR, cv2.BORDER_TRANSPARENT)

C++：`cv::getPerspectiveTransform(src4, dst4)` + `cv::warpPerspective`，同上。

### 2.4 验证

- 400 个随机图案点：图案 → 平面 → 3D → **真实相机解析投影**（算法看不到 K,R,t）
  与 `H·A` 对比，最大误差 `2.3e-13 px`（旧尺寸）/ `4.6e-13 px`（新尺寸）。
- 两条渲染路径（直接投影 vs 旧图经 `M` 搬移）差异 mean ≈ `1.9/255`，只出现在纹理边缘，
  纯属两次重采样，与几何无关。

### 2.5 工程注意事项

1. **必须用透视（单应），不能用仿射**。仿射贴合会丢掉透视缩短，看起来像“贴在屏幕上”。
2. **缩小时的走样**：`warpPerspective` 是点采样，图案被缩小很多时会摩尔纹。
   先按比例 `cv2.resize` 预缩小 / 超采样 2~3 倍，或对图案建 mipmap。
3. **遮挡**：真实场景中被挡住的部分，纯几何无法判断，需要深度/分割掩码/已知位姿。
4. **光度**：单应只管几何不管光照。叠到真实照片上通常要从旧矩形区域估增益/白平衡，
   再加一点运动模糊，否则很“贴”。
5. **数值敏感性**：与问题一相同（4 点定死、外插），角点噪声会被放大。
6. **绕向**：图案角点与目标角点的对应关系必须一致；旋向反了会得到镜像的图案。

## 4. 被问到过的几个细节

**Q：为什么相机参数能“凭空消失”？**
因为 `K` 只出现在 `H = K·[a₁ a₂ C_c]` 的左边，它和右边的平面坐标无法分开——
而我们要的恰恰是“平面坐标 → 像素”这个整体映射。相机参数只影响**怎么理解**这个映射
（分解成内参/位姿），不影响映射本身。只有需要“离面”的推理（遮挡、光照、真实尺寸）时，
才必须知道相机参数。

**Q：矩形中心的像是不是四个角点的平均？**
不是。透视下是**两条对角线的交点**（单应保持交比与共线）。只有当四个角点构成平行四边形
（近似仿射）时，才等于算术平均。

**Q：如果我还知道相机内参呢？**
那就可以把 `H = K·[r1 r2 t]` 分解出完整位姿（`solvePnP`/IPPE），之后任意改动矩形中心位姿
也能重投影。但本文的问题里不需要这一步。

**Q：为什么不直接用 solvePnP？**
`solvePnP` 需要内参和矩形真实尺寸；本文的前提恰恰是“没有相机参数”，只能走单应。
